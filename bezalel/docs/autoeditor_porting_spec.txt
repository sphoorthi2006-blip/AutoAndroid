PORTING SPEC: make_video.py to a Kotlin Android app

Source of truth: the desktop engine make_video.py (Python + ffmpeg). This spec lists every rule the Android app must copy. Where this spec and the Python file disagree, the Python file wins, except for the Android decisions in section 2.


1. PURPOSE AND GROUND RULES

- The app turns images + a master SRT + an original SRT + a voice-over (+ optional scene clips) into a 1080p MP4. It must give the same result as the desktop engine: same cut times, same clicks, same headings, same image crop.
- The user wants an EXACT copy of the desktop behaviour. Do not add features, change defaults, or "improve" rules.
- The user is not a developer and relies on the AI to write all code. Explain in plain language; give a full source ZIP after each stage and a short test list.
- The app is built in chat by Claude, in stages, and built to an APK through GitHub Actions.
- Language: Kotlin. No Python on the phone.


2. ANDROID DECISIONS (the only intended differences)

- Output is 1920x1080 only, H.264 + AAC, MP4 with the moov atom at the start (faststart equivalent).
- Frame rate: user chooses 30 or 60 fps. Default 30.
- Export must be fast: use the hardware encoder (MediaCodec) and a frame-exact pipeline. A still image costs almost nothing to encode, so only heading zoom frames and scene clips need per-frame work.
- Bundled assets: the click sound and the font PatrickHand-Regular.ttf. The built-in click is the one embedded in make_video.py (variable EMBEDDED_CLICK_B64): stereo, 16-bit, 44100 Hz, 0.405 s. Extract it to a WAV file and ship it in the app.
- Hard cuts between slides (the desktop default; --fade is 0).
- Scene clips use the default behaviour only: a short clip holds its last frame, a long clip is cut at the end, clip sound is muted, clip is fitted with black bars. No loop / slow / fast / keep-sound options.
- Fixed defaults (no settings screen): heading color #FFFFFF, heading size 200 (at 1080p), heading min size 80, heading zoom 0.12, text fade 0.3 s, click level -14 dB, click offset 0, clicks at clip start and end ON, headings ON.
- Scene clip names: any name; the cue number is read from the name (section 4).
- Images are named by plain cue number only (1, 2, ... 54 ...). The user provides an image for EVERY cue, including heading and subscribe cues.


3. INPUTS

- Images: folder, loose files, or a ZIP. Extensions: jpg, jpeg, png, webp, bmp. Ignore __MACOSX and files starting with a dot. The cue number is the number in the file name.
- Master SRT: decides how many slides there are and what each says.
- Original SRT (the TurboScribe one): decides WHEN each slide starts. Optional; with none, master start times are used and the app warns.
- Voice-over: mp3, wav, m4a, aac, flac, ogg.
- Scene clips (optional): mp4, mov, mkv, webm, m4v, avi.
- Click sound: the bundled one (a user file with "click" in its name may override it, as on desktop).
- Role detection when files come from one folder (as discover() does): the voice-over is the largest audio file whose name does not contain "click"; the master SRT is the SRT whose name contains "master"; the other SRT is the original. If no name contains "master": one SRT means master only; with several, the original is the one whose text contains "turboscribe", else the one with the most cues, and the other is the master. The user must also be able to pick each file by hand.


4. SCENE CLIP NUMBERING AND CHECKS

- Cue numbers are 1-based and refer to the master SRT.
- Name rule: a plain number (53.mp4, n53.mp4, anything_53.mp4) means cue 53. Two numbers joined by a dash (12-14.mp4) mean cues 12 to 14. With several numbers in a name, use the last number or range. Leading zeros are ignored.
- Before export show a list such as "53.mp4 -> cue 53" so the user can correct a wrongly read number.
- A clip REPLACES the image of every cue it covers. A clip numbered 1 replaces image 1, and so on.
- Errors (block export): a clip points outside 1..N (N = number of master cues); the second number is smaller than the first; two clips cover the same cue (check after sorting by first cue).
- Images numbered for cues under a clip are ignored; tell the user.


5. BLOCKING CHECKS BEFORE EXPORT

- Every master cue that is NOT covered by a clip must have an image (matched by cue number). If any are missing, show exactly which cue numbers are missing (for example "Missing images: 57, 98"), keep Export disabled, and re-check when the user adds files. This applies to heading and subscribe cues too, because the user provides an image for every cue.
- Extra images that no cue needs: warn, do not block.
- The two SRT files must look like the same script: if the word match is below 40 % (section 7), stop with: "the two SRT files don't look like the same script."


6. SRT READING

- Read as UTF-8 (drop a BOM), replace bad bytes. Normalise line endings to \n.
- Split into blocks on blank lines. In each block find the line with H:MM:SS,mmm --> H:MM:SS,mmm (a dot is accepted instead of the comma). Text = all following non-empty lines, each trimmed, joined with one space.
- Time in seconds = h*3600 + m*60 + s + ms/1000.
- A cue = (start, end, text). Cue numbers in the file are ignored; use position 1..N.


7. SLIDE START TIMES (the core timing rule)

Goal: a slide starts when its first word is spoken in the original SRT.

- With no original SRT: start = master cue start; all slides count as exact.
- words(text): lower-case, then every match of [a-z0-9']+ (ASCII only; other letters are dropped).
- Clean original text before splitting into words: remove the TurboScribe watermark ("transcribed by turbo scribe" with an optional "go unlimited to remove this message", optionally inside brackets), remove "go unlimited to remove this message", remove tags [music], (music) and the same for applause, laughter, silence, noise; collapse spaces. Master text is NOT cleaned.
- Word timeline of the original: for each original cue with at least one word, total = sum of word lengths (min 1); the cue's time span is shared out in proportion to word length. Word k starts at the running time t and ends at t plus (end-start)*len/total.
- Master word list: all words of all master cues in order, each tagged with its slide index.
- Match the two word lists with a sequence matcher that behaves exactly like Python difflib.SequenceMatcher(None, master_words, original_words, autojunk=False): repeatedly take the longest matching block (ties: earliest in master, then earliest in original), then recurse left and right of it; adjacent blocks are merged. Port this algorithm faithfully so results are identical.
- For each matched master word, record the original word's start and end time. matched = number of matched master words; ratio = matched / max(1, number of master words). If ratio < 0.40 the files do not match (error).
- Per slide: start = start time of its first matched word; spoken_end = end time of its last matched word (if any).
- Unmatched slides: if slide 1 has no start, set 0. Take the list of slides that have a start (known). For each consecutive known pair (a, b) and each k between them: m_a, m_b = master cue starts of a and b. If m_b > m_a: t = start[a] + (start[b]-start[a]) * (master_start[k]-m_a) / (m_b-m_a); otherwise t = start[a] + (start[b]-start[a]) * (k-a)/(b-a). lo = spoken_end[a] if k == a+1 and spoken_end[a] is set and non-zero; otherwise lo = start[k-1] + 0.05. Then t = max(t, min(lo, start[b]-0.05)); start[k] = min(t, start[b]-0.05).
- Slides after the last known one: start[k] = start[last] + (master_start[k] - master_start[last]).
- Slide 1 always starts at 0.
- Keep strictly increasing: if start[i] < start[i-1] + 0.05, set start[i] = start[i-1] + 0.05.
- Report to the user: word match percentage; which slides were placed by estimate; the biggest shifts versus master timestamps (more than 1 s, top 6); slides shorter than 1 s (not under a clip).


8. TOTAL LENGTH AND FRAMES

- total = max(last master cue end, voice-over length).
- Frame numbers: bf[i] = round(start[i] * fps) for each slide, plus a last entry total_frames = max(1, round(total * fps)). Use round-half-to-even like Python. Where bf[i] <= bf[i-1], set bf[i] = bf[i-1] + 1. Final total_frames = bf[N]. Slide i (0-based) shows frames bf[i] to bf[i+1]-1.
- All cuts are hard cuts on these exact frames.


9. WHAT IS SHOWN FOR EACH CUE

1. If a scene clip covers the cue: the clip (section 11).
2. Else, classify the master cue text:
   - contains the word "subscribe" (any case) -> subscribe slide: pure black picture, no text.
   - matches ^\s*\d+[\.\)]\s+\S (starts with a number, then a dot or bracket, then a space and text) -> heading slide.
   - otherwise normal -> its image.
3. Heading slide: black screen with the cue text (the text as written, including the number) in Patrick Hand, white, centered, with fade-in and zoom (section 10).

The image of a heading or subscribe cue is never shown; it is replaced.


10. HEADING TEXT

- Size: heading_size * H / 1080 = 200 at 1080p; min size 80; target width max_w.
- Font fitting: start at the size; measure the text width; if it fits max_w use it on one line. Otherwise new size = max(min, min(size-1, floor(size * max_w / width))) and repeat; stop when the size reaches the min. If it still does not fit at the min size, wrap.
- Wrapping: add words one at a time to a line while the line width <= max_w (a line always gets at least one word). Line height = floor(size * 1.25). Lines are centered horizontally, and the block is centered vertically on the screen.
- Single line: centered at the middle of the screen (horizontal middle, vertical middle of the text).
- Plain static text slide (used for subscribe, and when animation is off): max_w = 0.85 * W.
- Animated heading (the default): max_w = 0.86 * W / (1 + zoom), so the text still fits at full zoom.
- Animation per frame f (0-based) of the heading cue with N frames: p = clamp(f / N, 0, 1); p = p*p*(3-2p); zoom factor z = 1 + 0.12*p. The picture shown is the centered crop of the text layer of size (layer / z), scaled up to 1920x1080 (smooth scaling). Draw the text layer at 2x resolution for 1080p, then scale down, so text stays sharp.
- Fade-in from black: fade_frames = round(0.3 * fps). q = clamp(f / fade_frames, 0, 1); q = q*q*(3-2q); multiply the picture brightness by q.


11. SCENE CLIPS

- A clip covers cues first..last, so its slot = frames bf[first-1] to bf[last]-1 (all frames of those cues).
- Video: scale to fit inside 1920x1080 keeping aspect ratio, pad with black bars centered, never stretch. Resample to the chosen fps.
- Clip shorter than the slot (by more than half a frame): hold the last frame until the slot ends. Clip longer: cut at the end. Clip sound is muted.
- Clips start at the slot's first frame.


12. PICTURES

- Apply EXIF rotation, convert to RGB.
- Cover-crop to 16:9: scale = max(W / w, H / h); new size = max(W, round(w*scale)) by max(H, round(h*scale)); high-quality resize (Lanczos or best available); crop the center to exactly 1920x1080. Never stretch.


13. CLICK TRACK AND AUDIO MIX

- Click time list (seconds = frame / fps), in order:
  - Every normal, subscribe and heading cue except the very first cue: a click at its start frame.
  - A scene clip that does not start at cue 1: a click at its start frame (clips-click option is ON). The cue after a clip also gets its click as usual.
  - No click at time 0.
- Click sound preparation: convert to mono, 44100 Hz. Trim: keep from the first sample whose absolute value exceeds 10^(-45/20) (about -45 dBFS) to the last such sample plus 0.03 s. Apply a linear fade-out over the last 0.02 s.
- Loudness: measure the integrated loudness of the voice-over in LUFS (ITU-R BS.1770-4, with the standard -70 LUFS absolute and -10 LU relative gates, as ffmpeg ebur128 does). If it cannot be measured use -20.
- Gain: rms_db = 20*log10(max(rms of trimmed click, 1e-6)); gain_db = LUFS + (-14) - rms_db; peak limit: gain_db = min(gain_db, -3 - 20*log10(max(click peak, 1e-6))); gain = 10^(gain_db/20).
- Click track: silent mono track of length total + 1 s at 44100 Hz; at each click time (offset 0) add the click multiplied by gain at that sample position; clip the sum to -1..1.
- Mix: voice-over resampled to 44100 Hz stereo, click track as stereo (both channels equal); sum them with no normalization, then a limiter with ceiling 0.95. Output length = total seconds (a shorter voice-over is padded with silence). Encode AAC 192 kbps.


14. REPORT

Beside the video, write <video name>_report.csv (UTF-8 with BOM) with columns cue, start, end, source, replaced_image, text (first 80 characters). Start and end are bf/fps with 2 decimals. source = image file name, or "SCENE <file>", or "TEXT SLIDE (heading, fade-in + zoom)" / "TEXT SLIDE (subscribe)". Also show: how many images were used out of how many given, and which were not used.


15. ANDROID RENDERING NOTES

- Pipeline: frames -> MediaCodec H.264 encoder through an input Surface (OpenGL), audio -> AAC encoder, MediaMuxer to MP4. Timestamp every frame as frame_index / fps so cuts are frame exact.
- Hold still slides by re-drawing the same texture; do not decode an image twice per run. Decode one image at a time (down-sample on decode) to keep memory low. 150+ images must not be loaded at once.
- Heading frames are drawn per frame (crop + scale + brightness) from one 2x text bitmap. Scene clips are decoded with MediaExtractor + MediaCodec to a Surface and drawn with letterbox.
- Use constant-quality or a high bitrate (for example about 12 Mbps) so stills stay sharp. Keyframe at least every 2 s.
- Show a progress bar; keep the screen awake while exporting; let the user cancel. Videos are about 10 minutes with 150+ images.
- 4K is not offered.


16. VERIFICATION AGAINST THE DESKTOP ENGINE

- Run the same files through the desktop engine and the app. Compare the report CSVs: slide start times must match within 1 frame, and the click times must match.
- Check by eye: heading text size and position, zoom and fade; subscribe slides are black; clips replace the right cues.
- Check speed and phone temperature on a full 10-minute project.


17. BUILD STAGES

1. Project, file inputs, cue numbering, scene clip name reading, missing-image screen.
2. SRT reading and timing (section 7), checked against desktop results.
3. Slides: pictures, heading text with the bundled font, zoom and fade.
4. Audio: loudness, click track, mix.
5. Export: encoder, scene clips, progress screen.
6. Full 10-minute test with 150+ images.
